# technoon.ai — full site audit, 2026-08-16

Scope: every file under `site/`, plus `vercel.json`. UI/UX, accessibility,
security, vulnerability surface, prompt-injection surface, and search/answer
engine readiness. Client asked for report **and** fixes, so the first section is
what was changed in this push and the second is what was deliberately left.

Method: static read of all first-party HTML, CSS and JS; `review/verify-spine.mjs`;
`review/verify-contrast.sh`; live load in Chrome at 1568px and in a 372px iframe;
grep sweeps for XSS sinks, secrets and banned copy.

---

## Fixed in this push

**1. The site shipped no security headers at all.** `vercel.json` now sets a
Content-Security-Policy, HSTS, `X-Content-Type-Options`, `Referrer-Policy`,
`X-Frame-Options` and a `Permissions-Policy` that turns off camera, microphone,
geolocation, payment and USB. The CSP is tight rather than nominal:
`default-src 'self'`, `object-src 'none'`, `base-uri 'self'`, no
`script-src 'unsafe-inline'` — the one inline script in `<head>` is allowed by
its SHA-256 hash instead. Only three external origins are permitted at all
(Google Fonts CSS, Google Fonts files, Cal.com frames).

`style-src` does keep `'unsafe-inline'`, and that is not laziness: the sticky
stack passes `--i` and the dealt tiles pass `--nth` as inline `style` attributes,
which CSP treats as inline styles. Removing it would mean removing the mechanism.

**2. Keyboard focus was invisible inside the new form.** The restyled fields are
borderless, and `.enq-input:focus { outline: none }` is two components of
specificity against the page's global one-component `:focus-visible` rule, so it
silently won and left anyone tabbing through a focus-trapping modal with no
indicator. WCAG 2.4.7. The ring is explicitly restored on `:focus-visible`. The
ribbon underline is a state change, not an indicator — at its cyan end it is
about 2.2:1 on the panel, under the 3:1 that a focus indicator needs.

**3. Heading semantics were inconsistent across the film.** HR SOLUTIONS,
CUSTOM SOLUTIONS and CUSTOMER SUCCESS each carried their function name in an
`<h2>`. MARKETING, SALES and OPERATIONS carried theirs in a `<p class="kicker">`,
with the *pain line* as the `<h2>`. So the three functions a search engine most
needs to associate with this page were the three whose names were not headings,
and a screen-reader user navigating by heading heard three pain statements
instead of three function names. The name is now the heading in all six, and the
line beneath it is a `<p>`. Nothing moved visually: `.say` and `.kicker` both set
their own margin, size and weight, and there is no element-level `h2` rule in the
stylesheet.

**4. Nothing on the page was machine-readable.** No canonical, no `robots.txt`,
no sitemap, no structured data, and a `<title>` that was the brand name alone.
All added. See the search section below.

**5. The enquiry card overflowed its own `max-height` by 29px** at 1568x745,
putting a scrollbar down the side of a card that had nothing worth scrolling to.
Fixed by giving the optional textarea an explicit height instead of letting the
`rows` attribute set it. It now fits exactly, and still scrolls on a short
laptop, which is correct.

**6. The nav asked for the same click twice.** `Free Audit` and
`Book free audit of your business` both opened the same calendar. That had been
a standing flag in `CLAUDE.md` with no resolution. The client's revert
instruction closed it: the quiet pill opens the calendar, the primary opens the
enquiry form, and those are the only two shapes an enquiry takes.

## Vulnerability surface

**Cross-site scripting: clean.** There is no `innerHTML`, `outerHTML`, `eval`,
`new Function` or `document.write` anywhere in the first-party JavaScript. Every
string on the page is authored HTML. The split-text effect works on `textContent`
and element nodes. There is no route by which text becomes markup.

**Third-party message handling: correct.** `cal.js` listens for `postMessage`
from the Cal.com embed and checks `e.origin` against an explicit two-entry
allowlist before reading anything off `e.data`. That check is the only thing
standing between an embedded third party and this page, and it is present and
placed first.

**Secrets: none.** No API keys, tokens or credentials anywhere in the repo.

**Deployment surface: correct, and worth re-verifying after every deploy.**
`outputDirectory: "site"` is what keeps `review/` (raw footage, tooling, 60MB of
stills) and `brief/` (client source material) off the internet entirely. After
the next deploy, confirm that `https://<domain>/review/room-sd-1.jpg` returns
404. If it returns an image, that setting has been widened and everything in
those two directories is public.

**The Cal.com iframe carries no `sandbox` attribute.** Cross-origin isolation
already prevents it from touching this page's DOM, so this is hardening rather
than a hole. `sandbox="allow-scripts allow-same-origin allow-forms allow-popups"`
is worth testing, but it needs a real booking put through it first — a sandbox
that is one token short breaks the flow silently.

## Prompt injection

**There is no LLM in the loop on this site,** so there is no classic injection
path: nothing on the page is generated from a model at request time, and no
visitor-supplied text is ever rendered back to a page or fed to a model.

Two things are worth the client knowing anyway.

**Outbound — the site now speaks to models on purpose.** `site/llms.txt` and the
JSON-LD graph exist to be read by ChatGPT, Perplexity and Google's crawlers.
`llms.txt` ends with a short "Notes for anyone quoting this" block: how the name
is spelled, which contact routes are real, and an instruction not to estimate
figures the site does not publish. That is text addressed to a model, and it is
there deliberately — it pushes toward accuracy about the client and says nothing
about anyone else. It is disclosed here so nobody discovers it later and reads it
as something hidden.

**Inbound — the enquiry form is the one untrusted channel, and it points at a
human inbox.** Whatever a visitor types arrives at `info@technoon.ai`. That is
harmless while a person reads it. It stops being harmless the moment that inbox
is wired into an AI assistant that can act — draft replies, file records, call
tools — because the message body is then attacker-controlled text arriving inside
a trusted context. This is a live consideration for an agency whose own product
is AI agents operating a business: the rule to carry into every client build is
that inbound content is data, never instructions.

## Search and answer engines

The page is one HTML document with every string present in the markup, so a
crawler that never runs the scroll still reads the whole story. What it lacked
was anything telling it what it was looking at.

Added:

- `site/robots.txt` — allows everything, and names 21 crawlers explicitly in two
  groups. The retrieval bots (`OAI-SearchBot`, `ChatGPT-User`, `PerplexityBot`,
  `Perplexity-User`, `Claude-SearchBot`, `DuckAssistBot`, `Applebot`) are the
  ones that make this page eligible to be cited inside an AI answer, and blocking
  them is the most common way a site disappears from AI search without anyone
  noticing. The training bots are listed separately so the client can opt out of
  training later without also opting out of being citable.
- `site/sitemap.xml`, referenced from `robots.txt` and from `<head>`.
- `site/llms.txt` — the whole site flattened into quotable prose, with an
  explicit statement that no pricing, case studies, client names or performance
  figures are published, so a model asked for those says so instead of guessing.
- A JSON-LD `@graph` in `<head>`: `Organization` + `ProfessionalService`,
  `WebSite`, `WebPage`, an `ItemList` of the four process steps, and an
  `OfferCatalog` carrying all six functions and all 25 named offerings with their
  descriptions. Verified: 4 nodes, 6 catalogs, 25 offers, no dangling `@id`.
- `<link rel=canonical>`, a full `robots` meta with `max-snippet:-1` and
  `max-image-preview:large`, `og:site_name`, `og:locale`, image dimensions and
  alt text.
- A descriptive `<title>`.

Every string in the graph is copied verbatim from the visible page, which is
Google's stated requirement. Nothing invented: there is no rating, review,
founding date, address, headcount or client name in it, and the check script
fails the build if one appears.

## Left deliberately, with reasons

**1. No privacy policy or data handling statement.** This is the largest gap on
the site. A business proposing to operate another company's sales pipeline and HR
records has no page saying what it does with data, and now has a form collecting
names and email addresses. It is a trust signal, a likely legal requirement, and
the thing a cautious buyer looks for before booking. It needs client input, not
a developer's guess.

**2. No FAQ block.** The single biggest remaining lever for being quoted by
ChatGPT and Perplexity, because those engines lift Q&A close to verbatim. Seven
answers are drafted in `brief/faq-for-approval.md` using only facts already on
the site. It is not shipped because the Text law requires client sign-off on
visible copy, and because Google treats FAQ markup whose answers are not visible
on the page as a policy violation.

**3. Google Fonts is a third-party request on every load.** It sends every
visitor's IP address to Google before the page has painted, and costs a DNS
lookup, a TLS handshake and a round trip on the critical path. Self-hosting
Familjen Grotesk and Hanken Grotesk is roughly a half hour of work and is a
privacy and performance win with no design cost. Not done here because it changes
how the design system is delivered and that deserves its own change.

**4. The film is 12MB.** The `saveData` and 2g bail already exists and lands
cleanly on the poster, but a phone on a normal 4G connection still downloads the
whole thing. Worth revisiting only if analytics show it mattering.

**5. `.cta--nav` is hidden below 400px.** That rule predates this push, when it
hid a duplicate of the calendar CTA beside it. It now hides the only nav route to
the enquiry form. At 372px the bar cannot fit a mark, an address and two actions,
so something has to give, and the calendar pill is the shorter of the two. The
form is still reachable on those phones from the arrival section and from inside
every function card, and the address is in the footer. Flagged rather than
changed, because the alternative is removing the calendar from small phones
instead.

**6. The Cal.com event title is spelled `Technoon.ai`.** Capital T, against the
spelling law, and visible to every single person who books an audit. It lives in
the Cal.com dashboard, outside this repo and outside the reach of any check here.
Client action.

**7. The mid-scroll state of the new process animation is unverified.** The
mechanism is confirmed — the ViewTimeline is attached and active, `animation-range`
resolves, `animation-duration` is `auto`, and the timeline's `currentTime` tracks
scroll correctly. What could not be confirmed is the interpolated output, because
Chrome does not produce frames for a background tab and the automation tab is
always backgrounded. This is the same class of harness limit already documented
for `dialog` `close` events. It needs one look by a human on a focused window.
